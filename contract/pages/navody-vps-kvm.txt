====== KVM a libvirt uvnitř VPS ======

VPS může sloužit jako hostitel dalších virtuálních strojů. Vnořená virtualizace
má režii navíc a výkon závisí na zatížení fyzického uzlu, proto není náhradou za
dedikovaný server. Tento návod používá aktuální šablonu **Debian (latest)**,
libvirt a systémové spojení ''qemu:///system''.

===== Dostupnost KVM =====

<vpsadmin-nav id="vps.features.open">
Funkce **KVM** a **TUN/TAP** jsou u nových VPS zapnuté ve výchozím nastavení.
Není třeba měnit nastavení ZFS ani VPS. Po přihlášení ověřte zařízení:
</vpsadmin-nav>

<code bash>
#!/usr/bin/env bash
set -euo pipefail

test -c /dev/kvm
test -r /dev/kvm
test -w /dev/kvm
test -c /dev/net/tun

printf 'KVM and TUN/TAP devices are available.\n'
</code>

Pokud kontrola selže, restartujte starší VPS, u které jste právě změnili funkce,
a znovu zkontrolujte její detail ve vpsAdminu. U nové VPS kontaktujte podporu;
nevytvářejte náhradní zařízení ručně.

{{:cs:screenshots:vpsadmin:vps-details:feature-settings.png?direct|Výchozí funkce VPS}}

===== Instalace libvirt =====

Nainstalujte QEMU, libvirt a ''virt-install'' z Debianu:

<code bash>
#!/usr/bin/env bash
set -euo pipefail

export DEBIAN_FRONTEND=noninteractive
apt-get update
apt-get install --yes \
  libvirt-clients \
  libvirt-daemon-system \
  qemu-system-x86 \
  qemu-utils \
  virtinst

systemctl enable --now libvirtd.service
virsh --connect qemu:///system version
</code>

Používejte systémové spojení ''qemu:///system''. Pro vzdálenou správu použijte
libvirt přes SSH, například ''qemu+ssh://root@HOST/system'', a chraňte SSH
klíčem. Nezveřejňujte nešifrovaný libvirt TCP socket do internetu.

Následující izolovaná doména bez disku a sítě pouze ověří, že libvirt opravdu
spustí QEMU s KVM. Neinstaluje operační systém:

<code bash>
#!/usr/bin/env bash
set -euo pipefail

domain=${DOMAIN_NAME:-kb-kvm-smoke}
xml=$(mktemp)
trap 'rm -f "$xml"' EXIT

cat >"$xml" <<EOF
<domain type='kvm'>
  <name>${domain}</name>
  <memory unit='MiB'>256</memory>
  <vcpu>1</vcpu>
  <os>
    <type arch='x86_64' machine='pc'>hvm</type>
    <boot dev='hd'/>
  </os>
  <devices>
    <emulator>/usr/bin/qemu-system-x86_64</emulator>
  </devices>
</domain>
EOF

virsh --connect qemu:///system create --validate "$xml"
virsh --connect qemu:///system domstate "$domain"
virsh --connect qemu:///system destroy "$domain"
</code>

Pro skutečnou instalaci pak vytvořte doménu s ''virt-install'' nebo
''virt-manager'', přidejte instalační ISO a disk a ponechte zatím
''--network none''.

==== Síť vnořeného stroje ====

Síť pro vnořený virtuální stroj není součástí tohoto návodu. Hostitelská VPS
obvykle dostává směrovanou veřejnou IPv4 ''/32'', privátní IPv4 ''/32'' s NATem
na routerech vpsFree.cz a IPv6 ''/64''. Běžné návody s ethernetovým bridgem a
DHCP proto nelze bez úprav použít. Ověřený postup pro směrovanou síť bude
zveřejněn samostatně; tento návod záměrně nespouští žádné síťové příkazy pro
hosta.

===== Diskové obrazy a ZFS =====

Kořenový dataset VPS je pro obrazy disků dostačující. Samostatný
[[navody:vps:datasety|subdataset]] je volitelný a dává smysl, když chcete
oddělenou kvótu, snapshoty, zálohovací plán nebo později měřit a ladit vlastnosti
pro tuto konkrétní zátěž. Nový subdataset je samostatná zálohovací jednotka;
ověřte proto jeho [[navody:vps:exporty|snapshoty a zálohy]].

{{:cs:screenshots:vpsadmin:vps-details:datasets.png?direct|Datasety VPS}}

Bez výsledků měření vlastnosti ZFS neměňte. Výchozí komprese zůstává zapnutá a
výchozí ''recordsize'' je 128 KiB. Hodnota 64 KiB není obecně nejlepší pro
všechny virtuální stroje. Změna ''recordsize'' navíc ovlivní nově zapsaná data,
nepřepíše již existující obraz.

Jednoduchý řídký obraz ''raw'' má nejméně vrstev a je dobrá výchozí volba.
''qcow2'' použijte, když potřebujete jeho backing files, interní snapshoty nebo
další obrazové funkce a přijímáte další metadata a copy-on-write vrstvu. Oba
typy lze vytvořit řídce:

<code bash>
#!/usr/bin/env bash
set -euo pipefail

image_dir=${IMAGE_DIR:-/var/lib/libvirt/images}
image_size=${IMAGE_SIZE:-1G}

install -d -m 0755 "$image_dir"
truncate -s "$image_size" "$image_dir/guest.raw"
qemu-img create -q -f qcow2 "$image_dir/guest.qcow2" "$image_size"

qemu-img info --output=json "$image_dir/guest.raw"
qemu-img info --output=json "$image_dir/guest.qcow2"
du -h "$image_dir/guest.raw" "$image_dir/guest.qcow2"
</code>

Virtuální velikost obrazu není totéž co skutečně alokované místo. Spotřebu mohou
držet data, metadata a snapshoty. Uvolňování bloků pomocí discard/TRIM funguje
jen tehdy, když je správně nastaven celý řetězec host–QEMU–host a je předem
ověřen na daném obrazu. Snapshot běžícího disku je obvykle pouze konzistentní
jako po pádu; pro aplikační konzistenci hosta pozastavte nebo quiescujte.

Podrobnosti k ladění podle zátěže popisuje [[https://openzfs.github.io/openzfs-docs/Performance%20and%20Tuning/Workload%20Tuning.html|OpenZFS Workload Tuning]], formáty obrazů pak [[https://www.qemu.org/docs/master/system/images|dokumentace QEMU]].

===== Instalační ISO na NFS =====

Instalační ISO je bezpečnější nejprve zkopírovat na lokální dataset. U staršího
NFSv3 exportu bez funkčního síťového zamykání může QEMU skončit chybou jako
''Failed to lock byte 100'' nebo ''Failed to get ... lock''.

Pouze pro jednoho klienta a pouze pro instalační ISO připojené pro čtení lze
použít ''nolock'':

<code bash>
#!/usr/bin/env bash
set -euo pipefail

: "${NFS_SERVER:?set NFS_SERVER to the NAS server address}"
: "${NFS_EXPORT:?set NFS_EXPORT to the exported dataset path}"

mountpoint=${ISO_MOUNTPOINT:-/mnt/installer-iso}
install -d -m 0755 "$mountpoint"
mount -t nfs -o ro,vers=3,nolock \
  "${NFS_SERVER}:${NFS_EXPORT}" "$mountpoint"

findmnt --noheadings --output FSTYPE,OPTIONS --target "$mountpoint"
</code>

''nolock'' vypíná síťové zamykání NLM a ostatní klienti pak nevidí lokální
zámky. Nikdy jej nepoužívejte pro zapisovatelný nebo sdílený disk virtuálního
stroje. U NFSv4 je zamykání součástí protokolu a tato volba není řešením. Viz
[[https://man7.org/linux/man-pages/man5/nfs.5.html|nfs(5)]].
